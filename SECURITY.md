# Безопасность

VPS-VPN Monitor управляет серверами с правами **root**. Ошибка или утечка данных с ПК даёт
полный доступ ко всем вашим серверам, поэтому ниже честно описано, что защищено, а что нет.

## Как сообщить об уязвимости

Не публикуйте уязвимость в открытом issue. Используйте
[приватное сообщение об уязвимости](https://github.com/qqoe-sys/vps-vpn-monitor/security/advisories/new)
на GitHub (вкладка **Security → Report a vulnerability**). Не прикладывайте реальные IP, ключи, UUID и ссылки подписок.

Поддерживается только последняя версия.

## Что хранится на ПК

Все данные лежат в `%APPDATA%\vps-monitor\` вашей учётной записи Windows:

| Файл | Что внутри | Насколько чувствительно |
|---|---|---|
| `keys\*_ed25519` | приватные SSH-ключи, созданные программой | **критично**: root-доступ к серверам |
| `servers.json` | IP, имена, роли серверов, лимиты, путь к ключу | личные данные |
| `subscriptions.json` | имена людей, секретные коды их ссылок | секреты: по коду выдаётся VPN-ключ |
| `inventory-cache.json` | копия списка клиентов входов (UUID) | секреты |
| `known_hosts` | отпечатки ключей серверов, которым вы доверились | не секрет, но важно для защиты от подмены |
| `traffic.json` | история трафика по ключам | личные данные |
| `settings.json` | язык интерфейса | не секрет |

**Ключи на диске не шифруются отдельно** — их защищает только ваша учётная запись Windows.
Рекомендации: пароль/ПИН на учётной записи, BitLocker (или шифрование устройства), не давать
другим людям вход под своей учётной записью, не синхронизировать `%APPDATA%` в облако.

## Что сделано для защиты

**Приложение (Electron)**
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`: интерфейс не имеет доступа к Node.js и файлам;
  всё опасное (SSH, ключи, запись файлов) — только в главном процессе через узкий `preload`.
- Строгая CSP: `script-src 'self'` — внедрённые в страницу скрипты не выполнятся.
- Переходы на внешние страницы и новые окна запрещены; из разрешений браузера оставлен только буфер обмена.
- Данные с серверов выводятся в интерфейс через экранирование HTML.
- Запуск второй копии блокируется (иначе две копии портили бы файлы статистики).

**SSH**
- Ключ сервера проверяется по `~/.ssh/known_hosts` и собственному списку доверия. Новый сервер —
  показ отпечатка и явное подтверждение; ключ изменился — подключения не будет.
- Пароль root вводится один раз при добавлении сервера, передаётся только в библиотеку SSH
  (не в командную строку и не в логи) и **не сохраняется**. Смена пароля root идёт через stdin `chpasswd`.
- Для каждого сервера создаётся отдельный ключ ed25519.

**Изменения на сервере**
- Всё, что программа создала (файлы, службы, пользователь `xray`, правила UFW), записывается в
  `/var/lib/vpsmon/manifest.json`; по нему работают откат и удаление настроек.
- Перед правкой конфига Xray — бэкап и `xray run -test`; если Xray не поднялся стабильно (5 секунд без
  перезапусков), конфиг откатывается автоматически.
- Изменения UFW и отключение входа по паролю — под «мёртвой рукой»: если программа не подтвердила,
  что доступ остался, systemd-таймер сам отменит изменение через несколько минут.
- В Xray запрещён доступ клиентов к внутренним адресам сервера (`geoip:private`, `127.0.0.0/8` и др.).
- Выходной сервер пускает на порт 443 только IP своих входов (правило UFW).
- Xray ставится из официальных релизов GitHub с проверкой контрольной суммы.
- Сайт подписок: только HTTPS (сертификат Let's Encrypt через Caddy), ссылки с кодом из 32 случайных байт.

## Известные ограничения

- Ключи и коды подписок хранятся на ПК в открытом виде (см. выше).
- Контрольная сумма Xray берётся из того же релиза GitHub: она защищает от повреждения файла,
  но не от взлома самого репозитория Xray.
- Установщик **не подписан** сертификатом разработчика — Windows SmartScreen покажет предупреждение.
  Проверяйте SHA-256 файла со страницы релиза (см. README).
- Встроенный терминал даёт полный root-доступ: всё, что вы в нём наберёте, выполнится на сервере.
- Программа работает от имени `root` и рассчитана на серверы, где ничего, кроме неё, не настроено.
  На сервере с другими службами она может конфликтовать по портам и правилам UFW.
- Сторонний аудит кода не проводился.

## Проверка репозитория на утечки

Перед каждым коммитом убедитесь, что в индекс не попали личные данные:

```powershell
git status --short
git grep -nE "BEGIN (OPENSSH|RSA) PRIVATE KEY|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}"
```

Ожидаемое совпадение — только вымышленный UUID `00000000-1111-2222-3333-444444444444` в `tools/subs-preview.js`.
В тестах нет реальных серверов: используются адреса для документации (`192.0.2.0/24`, `198.51.100.0/24`,
`203.0.113.0/24`, RFC 5737), условные адреса вроде `1.2.3.4` и домены `example.*`.
